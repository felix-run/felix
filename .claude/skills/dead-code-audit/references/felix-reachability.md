# Felix reachability channels

The repo-specific half of the **dead-code-audit** skill. Every one of these makes a symbol live while
a grep for its name finds nothing.

## Entry points to start from

`felix-api` (Granian/FastAPI, `apps/api/src/felix_api/main.py:create_app`), `felix-worker` and
`felix-scheduler` (Taskiq, `apps/worker/src/felix_worker/tasks.py`), the `felix` CLI
(`packages/cli/src/felix_cli/main.py`: `migrate | eval | mint-jwt | bundle-manifests |
validate-manifest | doctor | version | temporal-worker`), and Alembic (`migrations/versions/`).

## Channels that defeat grep here

| Channel | Where it lives | What it makes live |
|---|---|---|
| Import-time registry | `patterns/registry.py:register_pattern(...)` | A pattern module nothing imports by name is still reachable through `spec.pattern` |
| Plugin registry / entry points | `felix/plugins.py` and the `felix.plugins` entry-point group; `apps/api/src/felix_api/composition.py` is the only core file allowed to name a plugin | Routes, tools, authenticators, cron tasks, rate-limit keys registered from outside core |
| String-named manifest fields | `manifests/*.yaml` `spec.*`, resolved in `manifests/builder.py` | A binder or `apply_*` wrapper referenced only from YAML |
| Skill names in YAML | `spec.skills` naming `skills/<name>/SKILL.md` | A skill directory with no Python reference at all |
| Tool name construction | `server__tool` (MCP) and `peer__name` (A2A) are built at bind time | Handlers never named literally in source |
| Taskiq cron labels | Labels on tasks in `apps/worker/.../tasks.py` | Periodic jobs that only fire when `felix-scheduler` runs |
| Settings referenced from docs | `felix/config.py:Settings` fields | `test_env_example_documents_every_setting` requires every field appear as `FELIX_<NAME>` in `.env.example` — the doc reference is mandatory, not a caller |
| Generated / published files | `migrations/versions/*`, `schemas/manifest.schema.json` | Never delete or edit; the schema is regenerated by `make schema` |

## Things that look dead and are not

- **A manifest spec field with no consumer.** That is *inert*, not dead — the field parses but
  `builder.py` ignores it. `tests/unit/test_inert_manifest_fields.py` is the existing check. The fix
  is to wire it, not to delete it.
- **An optional-extra code path.** Anything behind `aws`, `gcp`, `mcp`, `browser`, `embeddings`,
  `warehouse`, `temporal`, `sandbox`, or `pii` is unreachable in a lean install by design. Absence of
  coverage under `memory://ci` is not evidence of deadness.
- **An in-memory store twin.** Required by `test_postgres_modules_have_an_in_memory_path` and used by
  every CI run.

## Sweeps this repo ships

```bash
# Import every submodule under a lean install — catches references extras were hiding
uv sync --locked --no-dev && uv run --no-sync python scripts/lean-import-check.py

# Structural invariants, including the plugin boundary and the memory:// twin rule
./scripts/test.sh tests/unit/test_invariants.py tests/unit/test_plugin_boundary.py -q

# Full suite — the caller you missed is somewhere you were not looking
./scripts/test.sh
```

`scripts/lean-import-check.py` walks `felix`, `felix_api`, `felix_cli`, `felix_worker` with
`pkgutil.walk_packages` and imports every submodule, precisely because a stray import in a module
nothing else pulls in stays invisible otherwise.

## Deleting a setting

A `FELIX_` setting is live in four places at once: `felix/config.py:Settings`, `.env.example`, the
README table, and possibly `deploy/docker/compose*.yml` plus `deploy/helm/felix/values.yaml`. Remove
all of them in the same change, or `test_env_example_documents_every_setting` and the operator's
deployment disagree about what exists.
