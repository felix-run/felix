# Felix quality hotspots and exemptions

The repo-specific half of the **code-quality** skill. Authoritative sources: `pyproject.toml`,
`.claude/rules/felix-invariants.md`, `tests/unit/test_invariants.py`.

## Lint rules disabled on purpose — not findings

`[tool.ruff.lint] select = ["E", "F", "I", "UP", "B", "ASYNC", "SIM", "RUF"]`, line-length 110,
`target-version = py314`. Everything in `ignore` is a decision with a reason on record:

| Rule | Why it is off |
|---|---|
| `B008` | FastAPI `Depends(...)` in parameter defaults is the framework's idiom |
| `ASYNC109` / `ASYNC240` | Intentional sync `Path`/timeout APIs in the CLI and approval waiters |
| `E731` | `now_ms = lambda ...` is the one-liner clock used across every store |
| `SIM102` | Nested auth/env guards are kept explicit because they read better than a merged `and` |
| `SIM108` | Ternary-instead-of-`if` hurts readability at this line length |
| `RUF001` / `RUF002` | En-dash in user-facing copy is intentional |
| `RUF034` | Also relaxed under `tests/**`, along with `E501` and `RUF012` |

Do not "fix" these and do not add a per-line `noqa` to route around one. If a rule genuinely should
come back, that is a `pyproject.toml` change with a reason, not a suppression.

## Type warnings that may hide real defects

`[tool.ty.rules]` downgrades six rules to `warn` so CI gates *new* import breakage without blocking
on pre-existing debt: `invalid-argument-type`, `invalid-assignment`, `invalid-await`,
`invalid-return-type`, `invalid-type-form`, `unresolved-attribute`. Unresolved **imports** stay
errors. Read the warnings on changed files — `uv run ty check packages apps` — and judge whether a
warning on new code is a defect. `make type` needs `make install-full`; a lean venv reports every
optional dependency as an unresolved import.

## Large by design — audit, do not refactor

- `packages/harness/src/felix/manifests/builder.py` — the compile pipeline. Its governance wrapper
  order (secret masking → policies → command screening → content screening → limits → guardrails →
  judges → approvals → artifact spill) is an invariant asserted by
  `test_governance_wrapper_order_is_unchanged`. Each wrapper clones the tool with a new executor, so
  order defines precedence. Extracting or reordering to reduce length changes behavior.
- `packages/harness/src/felix/config.py` — one `Settings` class on purpose; splitting it breaks the
  single-source-of-truth rule and `test_env_example_documents_every_setting`.
- `migrations/versions/*` — generated, published, and never edited.
- `schemas/manifest.schema.json` — generated by `make schema`; never hand-edited.

This list is exhaustive. A large file **not** named here has no such defense — see below.

## Large and undefended — splitting these is welcome

The section above was read as "every big file in this repo is deliberate," which is how
the two largest modules in the harness kept getting a pass. They are not defended:

- `packages/harness/src/felix/patterns/model.py` is **522 lines and under budget** — this
  entry described it at ~1,630 and named the wire-client split as the obvious next step long
  after that had happened. A stale hotspot map costs more than no map: it sends the next
  reviewer at work already done and away from the file that has grown since.

  Three splits got it there. The wire formats and neutral types moved to `packages/ai`
  (`felix_ai`), which is also what makes model-agnosticism structural rather than claimed.
  The GenAI span shaping moved to `observability/genai.py` — content capture, redaction and
  the semconv attribute writing are not model-specific. The resilience composites moved to
  `patterns/model_composites.py`: failing over and escalating are a policy about unavailable
  or inadequate answers, not routing.

  What remains is the module's actual subject: route resolution against `Settings`,
  `record_usage`, the traced client wrappers, and the provider factories.

  Note for anyone auditing metering: `model_composites.py` is in
  `_UNMETERED_BY_DESIGN` alongside `model.py` in `tests/unit/test_invariants.py`, for the
  reason that exemption always had — these hold clients, and metering is the caller's job.
  A *pattern* added to that set would be a bug.

`packages/harness/src/felix/patterns/__init__.py` was 920 lines and is now 152: the composite
agent moved to `patterns/delegating.py` and the deep pattern's plan tools to
`patterns/plan_tools.py`, which also removed both of that file's `noqa: E402` imports.
`delegating.py` is ~645 lines and holds one `_run_*` per pattern.

## Duplication that is a defect, not a counter-rule

Stream and non-stream implementations of the same behaviour are the one duplication in this
repo that has repeatedly shipped bugs, because the copies drift silently:

- `patterns/react.py` — `invoke` and `stream_events` were near-copies; the streaming half had
  stopped emitting `user_input` and `final_response` audit records entirely. Fixed by
  collapsing both onto `_run(input, *, emit_events: bool)`. Read that docstring first.
- `patterns/model.py` — a streamed turn was followed by a second `chat()` for the real answer:
  billed twice, metered once, so `limits.max_cost_usd` counted about half the spend. Fixed by
  `stream_turn`, which yields deltas and ends with the authoritative `ModelChatResult`.
- `patterns/__init__.py` — `_stream_parallel` and `_stream_plan_execute` never called
  `record_usage`, so streamed runs of those patterns were unbilled and escaped the token and
  cost budgets, while their non-streaming twins metered correctly. Fixed by collapsing
  `_DelegatingAgent` onto one `_run_*(input, *, emit_events)` per pattern, the same shape
  `react.py` uses; `tests/unit/test_pattern_metering.py` asserts the budgets move on both
  `invoke()` and `stream_events()`, parametrized so a reopened split fails.

All three are now written once. If you find yourself adding a `_stream_x` beside an `_x`, that
is the defect, not the design — thread `emit_events` through the one implementation instead.

## Duplication counter-rules specific to this repo

- **Store twins are two implementations, not one duplicate.** Every Postgres-touching module carries
  a `memory://` twin (`_use_memory` / `InMemory…`), enforced by
  `test_postgres_modules_have_an_in_memory_path`. That twin is the CI test path. Do not propose a
  shared base class.
- **Patterns and plugins are registered, not enumerated.** `patterns/registry.py` and
  `felix/plugins.py` mean similar-looking registration blocks are the extension seam working as
  designed.
- **`apps/api/src/felix_api/routes/` is one module per surface** (REST/SSE, `/v1`, A2A, MCP,
  management). Parallel route modules that look alike are the convention, not drift.

## Where to look first

```bash
git log --format= --name-only -200 | grep '\.py$' | sort | uniq -c | sort -rn | head -15
```

High-churn files carry the highest quality interest. `builder.py`, `config.py`, and the route modules
will always be near the top — weight the rest.
